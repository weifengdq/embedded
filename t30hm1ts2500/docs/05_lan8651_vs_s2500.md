# LAN8651 vs T30HM1TS2500 (S2500)

两者都是 **OPEN Alliance 10BASE-T1x MAC-PHY**（SPI 接口，TC6/TC10/TC14 相关特性），
因此 SPI 帧格式、chunk 机制、PLCA 行为高度相似；但**寄存器映射完全不同**，
驱动不能直接复用。本项目在 STM32F407（**历史平台，板子已损坏停用**）上分别实现过 LAN8651（旧工程）与 S2500，
可直接对比；当前 STM32 平台已换成 STM32H723。

> **目标读者**：手上已有 LAN8651 工程，要迁到 S2500（或反过来）的人。
> **一句话结论**：SPI 事务层可以复用经验，**寄存器层约 70% 必须重写**。

## 1. 规格对比

| 项目 | Microchip LAN8651 | onsemi T30HM1TS2500 |
| --- | --- | --- |
| 标准 | IEEE 802.3cg 10BASE-T1S | IEEE 802.3cg 10BASE-T1S |
| 主机接口 | OA-SPI（TC6），最高 25 MHz | OA-SPI，最高 25 MHz（VIO=2.5V 时 24 MHz） |
| chunk 大小 | 8/16/32/64 B | 8/16/32/64 B |
| TX / RX 缓冲 | 4 KB / 8 KB | 4 KB / 8 KB |
| MAC 地址 | 无出厂 MAC（需主机提供） | **出厂唯一 MAC**（MACID0/1 寄存器） |
| 地址过滤 | 私有 MAC 寄存器（哈希/特定地址） | 4 组 OA 标准过滤+掩码，支持广播/组播开关 |
| 统计计数器 | 私有 MAC STATS 寄存器 | OA 标准 35 个计数器（MMS1 0x30..0x52） |
| PLCA | 支持（ID/NCNT/TOTMR/Burst） | 支持 + **协调者冗余 CR**、**优先级模式**、Burst |
| PLCA 诊断 | 有限 | RXINTO / UNEXPB / BCNBFTO + BEACON 计数 |
| SQI | 不支持 | **SQI (3-bit) + SQI+ (5-bit)** |
| 线束诊断 | 不支持 | **HDD class 4**（开路/短路/单线/多余终端） |
| 拓扑发现 | 不支持 | **TC14**（距离/延时测量） |
| 时间戳 | TC6 32/64-bit（收发） | TC6 32/64-bit + TTSC A/B/C + 捕获/比较/PPS |
| 睡眠唤醒 | TC10 | TC10 + 本地 WAKE 引脚 + WAKE 转发 + INH |
| 数字 IO | 无 | DIO0/DIO1（LED/SFD/CLK25M/CMP/CAP） |
| 供电 | 3.3 V 单电源 | 3.3 V（VCC/VIO）+ VBAT（睡眠 3.3–48 V） |
| 温度 | −40…+125 °C | −40…+150 °C（AEC-Q100 Grade 0） |
| 封装 | QFN32 5×5 | QFNW20 4×4 |

## 2. 软件差异（移植要点）

| 层 | LAN8651 | S2500 | 影响 |
| --- | --- | --- | --- |
| OA-SPI 事务 | 相同 | 相同 | 可直接复用控制/数据事务代码 |
| 初始化 | MAC_NCR/NCFGR 等私有寄存器 | MCONTROL0/SYNC + 过滤器 | **必须重写** |
| TX/RX 使能 | MAC_NCR.TXEN/RXEN | MCONTROL0.TXEN/RXEN | 重写 |
| FCS | MAC_NCFGR.RFCS 可剥离 | 无剥离位，主机处理 | S2500 驱动需 CRC 校验+剥离 |
| PLCA | MMD31 私有地址 | MMS4 0xCA00.. | 重写 |
| 统计 | 私有 | MMS1 0x30.. | 重写 |
| 诊断 | 无 | MMS4 0xCC00.. | 新增 |

> 结论：S2500 的 OA-SPI 传输层可复用 LAN8651 的经验，但寄存器层约 70% 需要重写；
> 本项目 `common/s2500/s2500.c` 即为 S2500 原生实现。

## 3. 性能对比（2026-11-20，同总线同主机）

| 指标 | LAN8651（旧工程，STM32F407，历史） | S2500（本工程，HPM5361） | S2500（本工程，TC387） | 备注 |
| --- | --- | --- | --- | --- |
| 主机接口 | SPI 21 MHz，硬件 | SPI1 **25 MHz + HDMA** | QSPI2 **25 MHz + DMA** | — |
| TCP 下行 | 8.86 Mbit/s | **8.80 Mbit/s** | **8.80 Mbit/s** | iperf2 |
| TCP 上行 | 待测 | 7.0–8.02 | 8.80 | 板端作客户端 |
| 纯发送 bench | — | **10.0 Mbit/s**（833 fps@1500B） | 9.72–9.85 | 已到线速 |
| ping RTT | 待测 | **0.70 ms** | **0.609 ms** | — |
| PLCA 收益 | CSMA 6.72 → PLCA 8.86（+32%） | CSMA 混跑碰撞 9278 → PLCA 5 次 | 同左 | 见 [`docs/07_performance.md`](07_performance.md) |

> 结论：两者在同一条 10BASE-T1S 线上的**吞吐量级一致（8.8 Mbit/s 左右）**，
> 差异在寄存器层与诊断能力（SQI/HDD/TC14/协调者冗余）。
> 旧工程数据来源：`<workdir>/embedded/lan8651/stm32f407_lan8651/README_CN.md`。

## 4. 互操作

同为 IEEE 802.3cg + OA-SPI，但**总线侧**两者可以挂在同一条 10BASE-T1S 段上
（PLCA 参数一致即可），本项目在总线上同时挂了 S2500 节点与 USB-10T1S（LAN8670）
验证互操作。

> ⚠️ SPI 侧驱动不通用；不要把 LAN8651 的驱动直接接 S2500。

## 5. 迁移步骤（LAN8651 → S2500）

| # | 步骤 | 具体动作 | 验证 |
| --- | --- | --- | --- |
| 1 | 保留 SPI 事务层 | 12B 控制事务 / chunk 数据事务的**字节格式**基本一致，CS 时序、奇校验思路可直接用 | 逻辑分析仪看波形 |
| 2 | 重写初始化 | S2500 需要：等 RESETC → 置 `PHY CONTROL.LCTL=1` → 置 `MCONTROL0.TXEN/RXEN` → 关 `BCSF/MCSF` | `s2500 selftest` PASS |
| 3 | 重写 PLCA | `MMS4 0xCA00..` 而不是 LAN8651 的 MMD31 私有地址 | `PST=1`、`PLCADIAG=0` |
| 4 | 补 FCS 处理 | S2500 **不剥离 FCS**，接收必须 CRC32 校验后剥掉 4 字节 | ping 通、长度正确 |
| 5 | 换 MAC 地址来源 | S2500 有出厂唯一 MAC（`MACID0/1`），不再需要主机下发 | `s2500 info` 看到合法 MAC |
| 6 | 增加诊断 | SQI / HDD / TC14 / 统计计数器 | `s2500 sqi`、`s2500 hdd` |

## 6. 迁移时的 8 个陷阱

| # | 陷阱 | 后果 | 规避 |
| --- | --- | --- | --- |
| 1 | 直接复用 LAN8651 的初始化序列 | 芯片能读 ID 但收发全废（LCTL 没开） | 按 §5 步骤 2 重写 |
| 2 | 以为芯片会剥离 FCS | 帧长差 4 字节，ping 不通 | 驱动里校验并剥离 |
| 3 | 用 LAN8651 的寄存器地址 | 读写全错位 | 全部按 [`docs/04_register_map.md`](04_register_map.md) |
| 4 | PLCA ID 沿用 LAN8651 的编号规则 | `RXINTO`/`UNEXPB` | 按 [`docs/02_bus_plan.md`](02_bus_plan.md) 的规划表 |
| 5 | 没处理"非结束块 EBO 无效" | 104B 帧只重组出 41B | 非结束块整块 64B 拷贝 |
| 6 | 把 `BCSF/MCSF` 置 1 想"只收单播" | ARP 收不到，ping 直接失败 | 两位保持 0，用 `MADDRFILT` 做过滤 |
| 7 | 认为 chunk 大小可以随便改 | 驱动缓冲管理错乱 | 固定 CPS=6（64B） |
| 8 | 把 SPI 时钟拉到 30 MHz | 控制头偶发校验错 | ≤ 25 MHz（VIO=3.3 V） |

## 7. 常见错误与排查

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 移植后 `s2500 reg 0 0` 正常但 ping 不通 | LCTL/TXEN/RXEN 没开全 | 按 §5 步骤 2 逐位确认 |
| 能收 ARP 但回不了 ARP reply | TXEN=0 或 FCS 计算方式错 | 检查 `MCONTROL0.FCSA` |
| `s2500 info` 的 MAC 是 LAN8651 的本地管理地址 | 用了旧工程的 MAC 逻辑 | 改用 `MACID0/1` 读出厂 MAC |
| PLCA 打开后吞吐反而下降 | 任一节点 NCNT/TOTMR 不一致 | 全网统一 8 / 32 BT |
| HDD 一直报错 | 端接问题（与芯片无关） | 见 [`docs/02_bus_plan.md`](02_bus_plan.md) §6 |
