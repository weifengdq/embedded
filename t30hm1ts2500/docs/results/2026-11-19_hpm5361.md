# 实测记录 — 2026-11-19 HPM5361 + T30HM1TS2500

环境：Ubuntu 26.04 / USB-10T1S(192.168.10.10, PLCA 协调者) / HPM5361 (192.168.10.12,
PLCA id=2, 硬件 SPI) / 与 S32K312 板在同一段总线。

## 1. 芯片识别

```
$ s2500 info
 IDVER      : 0x00000011  (MAJVER=1 MINVER=1)
 PHYID      : 0x180FF411
 STDCAP     : 0x000005E3
 CONFIG0    : 0x00009806  [SYNC=1 ZARFE=1 CPS=6]
 MAC        : 44:9F:79:29:73:18
 PHY STATUS : 0x0829
 PLCA       : en=0 id=2 ncnt=8
 ONIPVER    : 0x30C0  ONICVER=0xA7A813D2
 DIOCFG0    : 0x0000CBDF  DIO0.FN=15 DIO1.FN=5
```

## 2. 自检

```
$ s2500 selftest
[1] SPI/寄存器   : PASS (IDVER=0x00000011)
[2] PHY ID       : 0x180FF411  MAC=44:9F:79:29:73:18
[3] PCS 环回收发 : PASS (rxlen=100 head=449F7929)
[4] PHY 环回收发 : PASS (rxlen=100 head=449F7929)
[5] PHY Status   : 0x082D link=1
[6] SQI/SQI+     : 1/7, 63/255
[7] HDD          : valid=1 SHORT_OPEN=2 (SHORT / 多余终端) 1W=1
```

## 3. 网络

```
$ netif
board : HPM5361 + T30HM1TS2500
mac   : 44:9F:79:29:73:18
ip    : 192.168.10.12/24  gw 192.168.10.10
link  : UP   plca id=2
```

主机：

```
$ ping -c 3 192.168.10.12
3 packets transmitted, 3 received, 0% packet loss
rtt min/avg/max/mdev = 0.679/0.859/1.190/0.234 ms
```

板端 ping 主机：`reply seq=0 time=1 ms` / `reply seq=1 time=1 ms`。

## 4. 吞吐（iperf2）

```
$ iperf -c 192.168.10.12 -t 10 -i 10 -f m
[  1] 0.0000-10.0000 sec  9.00 MBytes  7.55 Mbits/sec
```

纯发送（不经过协议栈）：

```
$ s2500 bench tx 1000 500
bench tx: 1000/1000 frames len=500 dt=420 ms => 2380 fps, 9523 kbit/s
```

## 5. HDD 诊断

```
$ s2500 hdd
HDD valid=1 ready=1 SHORT_OPEN=2 (SHORT / 多余终端) 1W_SHORT=1
```

与 S32K312 板一致（SHORT_OPEN=2），说明总线上并联的 49.9 Ω 终端偏多；
1W_SHORT=1 需结合实际接线复核（可能是单线对地/单线短路，也可能是门限敏感）。

## 6. 结论

* HPM5361 + 硬件 SPI：**7.55 Mbit/s TCP**（主机→板），纯发送 **9.52 Mbit/s**（接近线速）。
* 与 LAN8651 旧工程（8.86 Mbit/s TCP）同一量级，说明 S2500 驱动/SPI 通路已充分利用带宽。
* HDD 给出的"多余终端"提示与硬件分析一致。
