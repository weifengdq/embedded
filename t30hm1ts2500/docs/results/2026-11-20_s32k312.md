# 2026-11-20 S32K312 LPSPI0 硬件 SPI 打通记录

> 结论：**LPSPI0 可用，默认后端已从软件 SPI 切到硬件 SPI。**
> 平台细节、寄存器配置与完整排错见 [`s32k312/README.md`](../../s32k312/README.md) §9。
>
> 采集：2026-11-20 下午；3 节点总线（本板 + HPM5361 + TC387），主机 USB-10T1S 为 PLCA
> 协调者 ID 0，NCNT=8 / TOTMR=32，iperf2。

## 1. 根因

### 1.1 “每 4 字节重复首字”

- S32K312 的 LPSPI0 **FIFO 只有 2 个字深**（`PARAM=0x00080202`：TXFIFO=2 / RXFIFO=2）。
- 旧代码把 `FCR.TXWATER` 设为 3；RM 定义 `SR.TDF = (TXCOUNT <= TXWATER)`，于是 TDF 恒为 1，
  写循环从不等空位，**第 3 个字以后的所有 TDR 写被硬件静默丢弃**。
- S2500 只收到半个包头，回显 `HDRB=1` 变成 `0x40000000`，看起来就像“每个字都重复首字”。

### 1.2 打通后卡在 3.55 Mbit/s

- 接收路径每帧用**逐位 CRC32** 复核 FCS（1460B ≈ 60k 周期 ≈ 0.5 ms），串在
  “收完 → 交给 lwIP → 回 ACK”之间，把 TCP 窗口卡死。
- 改成**半字节查表**（结果与逐位实现完全一致，200 组随机数据比对）后 **3.55 → 6.26 Mbit/s**。

## 2. 最终配置

| 项 | 值 |
| --- | --- |
| 帧格式 | **32 位帧**（`TCR.FRAMESZ=31`，BYSW=0，MSB first，SPI mode 0） |
| SCK | **15.137 MHz**（功能时钟 60.55 MHz，`CCR1.SCKSET=SCKHLD=1`） |
| CS | PTB5 软件 GPIO，覆盖整笔事务；`TCR.CONT=1`，收尾写 `CONT=0` 结束 |
| FIFO 节拍 | 深度从 `PARAM` 现读；`FCR = TXWATER(depth-1) / RXWATER(0)`；写前查 `TXCOUNT<depth` |
| 引脚 | PTB4=SOUT / PTD15=SCK / PTD16=SIN / PTB5=CS |
| 后端 | 默认硬件；`s32k hw off` 运行时回退软件 SPI，`s32k hw on` 切回 |

## 3. 实测

| 项目 | 软件 SPI | LPSPI0 硬件 SPI |
| --- | --- | --- |
| IDVER 1000 次 | — | **bad=0、timeout=0**（18 ms PASS） |
| SPI 层（68B 事务） | ~2.9 Mbit/s | **13.27 Mbit/s** |
| TCP 下行（主机→板） | 1.17 Mbit/s | **6.26 Mbit/s**（安静总线；多人共用 3.5–4.6） |
| TCP 上行（板→主机） | 1.40 Mbit/s | **7.75 Mbit/s**（安静总线，低值 7.45） |
| ping RTT | 2–3 ms | **0.82 ms** |
| 驱动丢包 | — | rx drop / ovf / resync / fcs / parity 全 0 |
| 累计事务 | — | 63 万笔，超时 0 |
