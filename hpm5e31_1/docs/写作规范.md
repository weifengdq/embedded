# 写作规范（hpm5e31_1 技术文档集 / 书稿）

> 所有参与写作的 Agent 与人类贡献者必须遵守。写完必须通过 `python3 tools/check_docs.py`，
> 最终由 `tools/build_pdf.sh` 合成 PDF。

## 1. 目标读者与定位

- 读者：使用 HPM5E31 / HPM5E00 系列做嵌入式开发的工程师，具备 MCU 基础。
- 定位：**"能照着做完、能量化对比、能查错"** 的实战手册；不是寄存器手册的复述。
- 语言：简体中文；术语首次出现给英文缩写；数值带单位与出处。

## 2. 每章必备结构（缺一不可）

1. **文档信息表**：版本、适用芯片/板卡、对应例程目录、实测日期、可信度。
2. **本章导览**：读者能学到什么、前置章节。
3. **概述与典型应用**：一句话定位 + 应用场景 + 关键特性表。
4. **工作原理**：时钟树、数据通路、状态机、时序；示意图必须用脚本生成并放在 `docs/figures/<chapter>/`。
5. **关键寄存器与驱动 API 对照表**：寄存器 / 位域 / 驱动 API / 例程位置，至少 8 行。
6. **例程逐条讲解**：每个例程一张表（路径、覆盖特性、关键配置、实测现象、实测日志路径），
   并给 1 段关键代码（≤30 行）+ 关键配置数字（时钟/波特率/分频/位时序）。
7. **上板实测数据**：表格 + 图（波形/吞吐/延迟/误差），注明测量方法（串口日志/计时/对端工具）。
8. **性能与调优**：参数扫描、瓶颈分析、优化前后对比。
9. **易错点与注意事项**：编号列表，每条"现象 → 原因 → 解决"。
10. **优劣评价与同类对比**：与 HPM 其它系列、STM32/TC397 同类外设对比（表格，注明来源）。
11. **扩展阅读**：官方文档、开源代码、博客链接（Markdown 链接）。
12. **待确认项与风险**：未实测/有疑点的条目，写清验证方法。

## 3. 引用格式（强制，可回溯）

| 来源 | 写法 | 示例 |
|---|---|---|
| 数据手册 | `DS §x.y (p.N)` | `DS §5.3 (p.42)` |
| 用户手册 | `RM §章.节 (p.N)` | `RM §55.4.2 (p.951)` |
| 勘误 | `Errata E000xx` | `Errata E00038` |
| SDK 源码 | 路径:行 | `hpm_sdk/drivers/src/hpm_mcan_drv.c:120` |
| 例程 | 仓库内相对路径 | `samples/can/mcan_loopback/` |
| 实测证据 | 日志路径 | `logs/20261030-104826-letter_shell_basic.log` |
| 外部资料 | Markdown 链接 | `[HPM SDK](https://github.com/hpmicro/hpm_sdk)` |

- 页码用 **PDF 阅读器页码**（不是印刷页码）。
- 任何具体数字（频率、时序、吞吐、误差、寄存器地址）必须有出处或标注"实测"。
- **禁止编造**：不确定就写"待确认（需实测）"并登记到第 12 节。

## 4. 图与表

- 图必须**由脚本生成**（graphviz dot / matplotlib / mermaid-cli / drawio 导出），脚本放
  `tools/figs/<name>.py|dot`，产物放 `docs/figures/<chapter>/<name>.png`（PNG 300dpi 白底）。
- 正文用 `![图 4-1 说明](figures/04-gpio/fig-04-1-ioc-path.png)`，图题**必须**写了"图 X-Y"。
- 表必须有表头与编号（"表 4-1"），列数对齐；表格里的 `|` 要转义。
- 所有图/表都要在正文中被引用（"如图 4-1 所示"）。

## 5. 代码

- 代码必须来自本仓库**真实可编译**的例程；粘贴前用 grep 核对 API。
- 代码块标注语言；每段前说明"这段代码解决什么问题"。
- 例程目录结构固定：
  ```
  samples/<category>/<name>/
    CMakeLists.txt
    src/main.c
    README.md          # 现象、命令、实测日志、关键点
  ```
- 例程统一 `#include "bsp.h"`，`main()` 中先 `bsp_init()`，主循环调用 `bsp_shell_poll()`，
  并用 `SHELL_EXPORT_CMD(... | SHELL_CMD_DISABLE_RETURN, ...)` 注册调试命令。
- 每个例程必须给出**串口自证输出**（printf 关键数据），方便无示波器时验证。

## 6. 质量门槛（tools/check_docs.py 检查）

- 每章 ≥ 250 行、≥ 8 个 `##` 二级标题。
- 至少 3 张表、至少 2 张图、至少 1 段代码块。
- 必须有"参考来源"与"待确认项与风险"。
- 相对链接必须存在；不得有 TODO/TBD/待补充占位。
- 中文标点规范；不出现连续 3 个空行。

## 7. 提交与协作

- 只由 Lead 提交 git；成员把文件写进自己负责的目录。
- 文件归属：见 `docs/00-目录.md` 的"负责人"列。
- 修改别人负责的文件前先 `send_message` 协调。

## 8. PDF 书签与验收（强制）

> 2026-10-30 起，所有合成 PDF **必须带三级书签**；无书签或书签不完整视为构建失败。

- **层级要求**：1 级 = 章（第 N 章）/ 前置页（封面、版权页、目录、插图目录）；2 级 = 章内 `##` 小节；3 级 = `###` 小节。允许某章最深层只到 2 级（该章没有 `###`），但整本 PDF 的最大层级必须为 3。
- **实现方式**：`tools/build_pdf.sh` 在合并封面/正文后调用 `tools/pdf_toc.py`（PyMuPDF）写入书签并设置元数据（title 含版本、author）。**禁止**再用 `pdfunite` 合并（会丢失 outline）。
- **前置页书签**：封面（p.1）、版权页（p.2）、目录、插图目录，页码必须在最终 PDF 中真实存在。
- **必须校验**（退出码非 0 = 构建失败）：
  ```bash
  python3 tools/pdf_outline.py --check <pdf> --min-entries <章节数×2> --require-level 3
  ```
  `build_pdf.sh` 已内置该二次校验（条目数 < 章节数×2 或最大层级 < 3 直接 die）。
- **元数据**：PDF Title 必须形如 `HPM5E31 实战手册 vX.Y.Z`，Author 为 `hpm5e31_1 项目组`。
- **回归防护**：修改 `preamble.tex` / 合并逻辑后，必须跑一次合成并用 `pdf_outline.py --check` 复验；不要只看 `pdfinfo`。

## 9. 第五轮（2026-11-02）补充规则

1. **章节顺序**：全书按五部分组织（基础与工具 / 外设驱动与实测 / 系统与性能 / 应用层与实战 / 附录），
   附录为第 51 章、放在全书最后；章节顺序以 `docs/00-目录.md` 为准（由 `tools/gen_toc.py` 生成）。
   改章节顺序或编号时，必须同步 `tools/gen_toc.py`、`tools/gen_index.py`、`tools/gen_appendix_tables.py`、
   `tools/check_docs.py` 的 `REVIEW_CHAPTERS`，并跑一次 `build_pdf.sh` 验证书签。
2. **源码仓库**：公开镜像统一写 <https://github.com/weifengdq/embedded>（暂定，随书稿发布）；
   正文引用例程仍用仓库相对路径 `samples/...`，不写内网地址、内网主机名与个人目录。
3. **外部资料**：ref/ref2 的下载物一律给上游 GitHub 或厂商官网链接（总表见第 27 章表 27-10、27-11）；
   链接给不出（NDA/未公开）就写"厂商内部资料（未公开）"，不得只写本地路径。
4. **文风**：写完跑 `python3 tools/polish_check.py --file <章节>`（检查套话、超长句、机械连接词）。
   目标是把"手册腔"改成"工程笔记腔"：先给结论和数字，再解释为什么；少用连续排比和空洞形容词；
   每个"易错点"写清现象 → 原因 → 解决三段。
5. **待确认项**：每轮结束前逐条复核，只允许三种状态——"已实测（日期+数据+日志）"、
   "已定位/已修复（根因）"、"已知限制（为什么不能测 + 怎么测）"。禁止留着"待补/未做"的裸条目。
6. **图**：新图必须脚本生成；同一章图号连续；正文"如图 X-Y 所示"引用；禁止只放图不引用。


## 10. 公开发布约定（v1.6.0 起）

- **仓库**：<https://github.com/weifengdq/embedded>（`hpm5e31_1/` 子目录）；书稿 PDF 按版本单独分发，不入仓库。
- **脱敏**：正文、脚本、图源里不出现内网仓库地址、内网主机/IP、代理与个人目录；统一用 `<host>`、
  `<proxy>`、`$HOME` 占位，仓库内文件一律写仓库相对路径。
- **插图**：`tools/figs/` 脚本生成的 PNG 入库前跑一次 `python3 tools/compress_figs.py`
  （宽度 ≤1920 px、256 色调色板，全书约 9 MB；比原图大时保留原图）。
- **日志**：`logs/` 只保留书中直接引用的关键日志（约 470 条，见 `logs/README.md`），
  开发期全量日志与大体积 pcap 不随公开仓库分发。
- **门禁**：发布前依次跑 `python3 tools/check_docs.py`、`python3 tools/check_numbering.py`、
  `bash tools/build_pdf.sh`；PDF 必须带三级书签。
