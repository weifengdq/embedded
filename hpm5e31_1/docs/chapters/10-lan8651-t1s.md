## 10.2 本章导览

本章解决一个问题：**怎样在一颗没有以太网 MAC 的 MCU（HPM5E31）上，用 SPI 挂一颗 LAN8651 MAC-PHY，把板子接进 10BASE-T1S 总线**。

读完后你应该能：

- 说清 10BASE-T1S、MAC-PHY、OPEN Alliance TC6 三层的关系，知道为什么 MCU 只需要 4 根 SPI 线 + 1 根中断；
- 看懂 TC6 的控制事务帧（4 B 头 + 4 B×LEN + 4 B 忽略）和数据块（68 B chunk），能手算出任意一次读写的 SPI 字节流；
- 把 LAN8650/1 的启动序列（RESETC → 读 STATUS0 → 清 RESETC → 置 CONFIG0.SYNC）落到代码里；
- 按 AN1760 下发 LAN865x Rev.B0/B1 的 PHY 参数，并读回 Clause 22 PHY ID 自证；
- 用"echo 校验 + 三态测试 + 位翻转对照"三板斧定位"SPI 到底通没通"，而不是靠猜（第 10.9 节，本章最有价值的部分）。

前置章节：第 07 章（SPI 总线）、第 02 章（构建与烧写）。后续章节：第 11 章（PLCA、lwIP、性能）。

## 10.3 概述与典型应用

10BASE-T1S（IEEE 802.3cg）是**单对双绞线、10 Mbps、多点（P2MP）**的车载/工业以太网标准：一条 25 m 的"混合段"上最多挂 8 个节点，靠 **PLCA**（Physical Layer Collision Avoidance，物理层冲突避免）做无冲突仲裁。它和 100BASE-T1/1000BASE-T1 的点对点用法不同，**天生是总线型拓扑**，因此在车身域控、传感器环、电池管理（BMS）等"多节点、低速率、短距离、低成本"场景里替代 CAN FD。

HPM5E31 没有内置 10BASE-T1S 的 MAC。常见做法是用 **MAC-PHY**：芯片侧（LAN8651）实现 MAC + PHY + PLCA，MCU 侧只通过 **SPI + OPEN Alliance TC6** 协议发以太网帧和读写寄存器。对 MCU 来说，它"长得像"一个带 68 字节块缓冲的 SPI 外设。

## 10.4 工作原理

### 10.4.1 三层结构：MAC-PHY / TC6 / 主机

- **MAC-PHY（LAN8651）**：内部包含 IEEE Clause 4 MAC、10BASE-T1S PHY、PLCA 子层，以及一个 SPI 从机接口。它自己会做 MAC 地址过滤、FCS 校验/生成、PLCA 仲裁。
- **TC6**：定义 SPI 上"怎么描述一次寄存器访问"和"怎么切分以太网帧"。它把 SPI 事务分成两类：**控制事务**（寄存器读写）与**数据事务**（以太网帧块）。
- **主机（HPM5E31）**：只需要 4 根 SPI 线、1 根复位、1 根中断；软件上实现 TC6 帧格式 + LAN865x 寄存器配置即可。

### 10.4.2 TC6 控制事务

控制事务以 **32 位大端命令头**开始，格式见 DS Table 5-4（p.58）：

```text
bit31    DNC = 0          控制事务（数据事务为 1）
bit30    HDRB             MAC-PHY 回显"收到坏头"时置 1（主机发送时忽略）
bit29    WNR              1 = 写，0 = 读
bit28    AID              1 = 地址不自增（FIFO 访问用）
bit27:24 MMS              内存映射选择器（0 = TC6 标准/Clause22，4 = MMD31 厂商/PLCA，1 = MAC）
bit23:8  ADDR             寄存器地址
bit7:1   LEN              寄存器个数 - 1（0 表示 1 个，最大 128 个）
bit0     P                奇校验（使整个头中 1 的个数为奇数）
```

一次读事务在 SPI 上的字节流是 **4 B 头 + 4 B×LEN + 4 B 忽略**，而 SDO 相对 SDI **延迟 4 字节**返回：`rx[4..7]` 是命令头回显，`rx[8..]` 才是寄存器数据。图 10-2 画出了读、写、数据块三种帧的字节布局。控制头的位域与驱动 API 的对应关系汇总在表 10-2，启动序列涉及的寄存器在表 10-2 的 OA_CONFIG0/OA_STATUS0 两行。

![图 10-2 TC6 控制事务与数据块的 SPI 字节布局](figures/10/fig-10-2-tc6-spi-frames.png)

> **自证技巧**：任何一次控制读，只要比较 `rx[4..7]` 与 `tx[0..3]` 是否相等，就能判断"SPI 四线 + 帧长度 + 采样边沿"是否全部正确。本仓库把这一步做成了驱动的内建校验：不相等即返回 `-3` 并累加 `stat_ctrl_err`（见 `components/oa_tc6/oa_tc6.c` 的 `oa_tc6_read_regs()`）。

### 10.4.3 数据块与缓冲区信用

以太网帧被切成 68 字节的块：发送方向 `[4 B 数据头][64 B 负载]`，接收方向 `[64 B 负载][4 B 尾]`。数据头里的 `DATA_VALID/START_VALID/END_VALID/END_BYTE_OFFSET` 描述本块里哪一段属于一帧；接收尾里带 **TX credits**（还能塞几个块，5 bit）、**RX chunks**（还有几块数据要收，5 bit）以及错误标志。主机的发送节奏完全由 `tx_credits` 驱动——这就是为什么"一次 SPI 事务里塞多少个块"不是固定的，而是每次从上一块的尾部动态读出来。

### 10.4.4 启动与复位序列

图 10-3 是 LAN8650/1 的启动状态机（依据 DS §4.1.2 与 Figure 4-1，p.21–22）。要点：

1. 复位后芯片把 `STATUS0.RESETC` 置 1、把 `CONFIG0.SYNC` 与数据尾的 SYNC 清 0，并**拉低 IRQ_N**；
2. 主机必须读一次 STATUS0（确认是复位引起），再**写 1 清 RESETC**、**置 CONFIG0.SYNC=1**；
3. 之后芯片把数据尾的 SYNC 置 1 并**释放 IRQ_N**。如果此时 IRQ_N 仍为低，说明还有其它中断源（最常见是 PHY 的中断，见第 10.9 节坑 6）。

/* 控制读：4B 头 + 4B×LEN + 4B 忽略；rx 侧整体延迟 4 字节 */

}
for (uint8_t i = 0; i < length; i++) {

### 10.7.5 DIOA 引脚能做什么、不能做什么（LED / PPS）

板上 LAN8651 的 DIOA0、DIOA1、DIOA4 各接一颗 LED（原理图 `hpm5e31_1_sch.pdf`：DIOA0-R39-5.1K、DIOA1-R43-2.2K、DIOA4-R35-5.1K），所以很容易想当然地认为这三颗灯能分别指示 LINK/ACT/PPS。查数据手册后这个设想不成立。

表 10-6 DIOA 引脚可选功能（DS60001734E §3.4 Table 3-9）

| 引脚 | 输入功能 | 输出功能 |
|---|---|---|
| DIOA0 | Event Capture 0 | Event Generator 0 |
| DIOA1 | Event Capture 1 | Event Generator 1 |
| DIOA2 | ACMA 或 Event Capture 2 | Event Generator 2 |
| DIOA3 | Event Capture 3 | Event Generator 3 |
| DIOA4 | 保留（Microchip 测试用） | **1PPS**、Event Generator 2/3 |

结论：**LAN8651 没有 LINK/ACT LED 输出功能**（数据手册里的 "LED lighting" 是目标应用，不是片内 LED 控制器）。DIOA4 能输出 1PPS，但那是时间同步功能：要先建立 PTP/1588 时间基准，再写 PPSCTL（MMS4 地址 0x0239，DS §11.6.48），不是链路指示灯。因此在 hpm5e31_1 上：

- 板载三颗 DIOA LED 不能当作 LINK/ACT 指示；需要链路灯时用 MCU 侧 GPIO 把 PHY 链路状态映射出去，或直接看 `link` 命令；
- 要验证 DIOA4 的 1PPS：先建时间基准 → 写 PPSCTL 使能 → 示波器/频率计测 DIOA4（板上 LED 会 1 Hz 闪，可肉眼粗判）。

本轮用 `rd 0x00040239` 读 PPSCTL 得到 `0x00000000`（复位默认：PPS 未使能），证明 MMS4 的厂商寄存器窗口可访问（MMS 的访问方式见 10.4 节）。读回只能证明访问路径，不能替代 LED 目视，所以这一条按"器件能力已确认 + 目视待现场"处理。日志 `logs/20261102-124630-lan8651_spi_probe.log`。

## 10.8 性能与调优

对"控制通道"来说，性能要看的不是带宽而是**单次寄存器访问的耗时**，因为它决定了初始化耗时（表 10-7）：

表 10-7 控制事务耗时（实测，命令 `scan`）

| 传输方式 | SCLK | 一次 12 B 控制读耗时 | 备注 |
|---|---|---|---|
| 位翻转（10 nops 半周期） | ≈1.6 MHz | ≈60 µs（估算 96 bit × 2 × 310 ns） | 兜底通道，慢 5~6 倍 |
| 硬件 SPI2 | 1 MHz | 104.1 µs（实测） | 与 96 bit/1 MHz 理论值一致 |

## 10.9 坑与注意事项

> 每一条都是本仓库在这块板上真实踩过并验证过的，按"现象 → 原因 → 解决"写。

1. **现象**：SPI2 的控制读永远返回 `0xFF`（MISO 全高），写寄存器也不生效，但 SPI 传输本身返回成功。
   **原因**：**SPI2 的外设时钟门控没有打开**。板级 `clock.c` 是从 hpm5e00evk 派生来的，EVK 不用 SPI2，于是只有 `init_spi1_clock()/init_spi3_clock()`；`board_init_spi_clock(HPM_SPI2)` 走 `else` 分支直接 `return 0`，既不报错也不开时钟。寄存器写被静默丢弃，读回自然是复位值/浮空。
   **解决**：`boards/hpm5e31_1/clock.c` 增加 `init_spi2_clock()`（`clock_add_to_group(clock_spi2, 0)`），`board.c` 的 `board_init_spi_clock()` 改为 switch 覆盖 SPI0~SPI3；驱动在使用 SPI2 前必须调用 `board_init_spi_clock(BOARD_LAN8651_SPI)` 并用它的返回值当 `clk_src_freq_in_hz`。**注意：开时钟是必要条件但远不是充分条件**——只修这一条时 echo 依然是全 0xFF，还要继续修坑 2 的三层问题。

2. **现象**：硬件 SPI2 读出来先是全 `0xFF`（MISO 高阻）、后来变全 `0x00`（芯片被选中、SDO 被驱动为低），但 echo 永远不匹配；而 **同一组引脚用 GPIO 位翻转 SPI 完全正常**。SPI 传输 API 每次都返回"成功"，收发字节数都对。
   **原因（三层叠加，按发现顺序）**：
   - **① CS 从没真正由软件控制**：`spi_master_get_default_control_config()` 的 `common_config.cs_index` 默认是 `spi_cs_0 = 1`（不是 0），`spi_transfer()` 每次都把 `SPI_CTRL.CS_EN` 写成 1 → 硬件 CS0 一直使能；同时 `pinmux` 里 PA21 是 `SPI2_CS_0`。于是"硬件 CS"和"GPIO CS"两条路其实都走的是硬件 CS0，GPIO 写值根本到不了 pad。
   - **② 只改一处不够**：必须**同时**把 PA21 改成 `GPIO_A_21`、把 `SPI_CTRL.CS_EN` 清零（`cs_index = 0`），并由软件按"CS 低 → 1 µs → 传输 → 1 µs → CS 高 → 1 µs"驱动。这两步在本仓库的 `pinmux_net1.c` / `oa_tc6.c` 里都做了（旧版本只做了其中一步，所以测试结论是"GPIO CS 也不行"——那个结论是错的）。
   - **③ 决定性根因：SPI2 的 SCLK pad 少了 `LOOP_BACK`**。HPM 的 SPI 主机需要把自己的 SCLK 经 pad 回环读回作为移位时钟：SDK 自动生成的 pinmux 在 SCLK pad 上一直带 `IOC_PAD_FUNC_CTL_LOOP_BACK_MASK`（见 SDK 板级 `pinmux.c` 的 `init_spiX_pins()`），本板手写 `pinmux_net1.c` 时漏了这个位。后果是：控制器"发完 12 字节、也读回 12 字节"，但 SCLK 没有真正驱动到引脚，LAN8651 收不到任何时钟 → SDO 保持空闲电平。
   **解决（四步，全部已落地）**：
   1. `board_init_spi_clock(HPM_SPI2)` 真正开 SPI2 时钟（坑 1）；
   2. CS 全程软件控制：PA21 = `GPIO_A_21` + `SPI_CTRL.CS_EN = 0` + 三段 guard 时序；
   3. **`PA20.FUNC_CTL = IOC_PA20_FUNC_CTL_SPI2_SCLK | IOC_PAD_FUNC_CTL_LOOP_BACK_MASK`**（本次修复的核心）；
   4. 长事务用 FIFO 感知的传输函数：`hpm_spi_transmit_receive_blocking()` 在超过 RX FIFO 的事务（16 寄存器块读 72 B、多块数据帧）会丢 RX 字节导致错位，改用底层 `spi_transfer()`（内部 `spi_write_read_data` 带 FIFO 重试）后 72 B / 1632 B 事务全部正确。
   **不依赖示波器的判据**：硬件 SPI 写 `OA_CONFIG0 = 0x00001234`，再用位翻转读回 —— 修复前写不进去；修复后硬件 SPI 的 echo 直接给出 `20 00 04 01 | 00 00 12 34`（命令头回显 + 写入值回显），证明 CS/SCLK/MOSI/MISO 四条线全部到位。
   **修复后**：1/2/5/10/20 MHz 各 32 次控制读 **0 错误**（表 10-5）；数据通道 20 MHz 下 60 B 帧 **18 489 帧/s、8.87 Mbit/s**，1518 B 帧 **9.08 Mbit/s**（第 11 章表 11-11）。

3. **现象**：读 Clause 22 PHY ID 得到 `0x1EA20000` 之类的垃圾值，PLCA 状态全 0。
   **原因**：**把 Clause 22 寄存器当成了 MMS=0xFF 的空间**。DS §11.1（p.111）明确写："Clause 22 CSR 在 MMS0 中，起始偏移 0xFF00"，即命令头 MMS 字段仍为 0、地址为 `0xFF00 | regnum`；而 Linux 驱动里的 `OA_TC6_PHY_STD_REG_ADDR_BASE = 0xFF00` 是**地址**的一部分，不是 MMS。作者第一版把 `(mms<<16) | reg` 套进来，等于访问了 `0x00FF0002` 这个不存在的空间。
   **解决**：`oa_tc6_c22_read()/oa_tc6_c22_write()` 直接用 `oa_tc6_read_reg(0xFF00 | (regnum & 0x1F))`。修好后 Clause 22 reg2/3 读到 `0x0007C1B3`，一次命中。

4. **现象**：单寄存器读偶尔返回"上一个寄存器"的值（例如读 `STATUS0(0x0008)` 得到 `STDCAP` 的 `0x0005E5`），而一次读 16 个连续寄存器的结果完全正确。
   **原因**：位翻转传输在 1.6 MHz 下，单寄存器读的采样余量偏小（`bb_half_delay` 太小），个别位的 MISO 采样点落在数据跳变附近；`rx[4..7]` 的 echo 仍然匹配（因为整帧一起偏移），所以驱动不会报错，但 `rx[8..11]` 的数据可能错。
   **解决**：① 关键寄存器用**多寄存器块读**（`oa_tc6_read_regs()` 一次读 0x0000~0x000F，原子且不依赖单次采样余量）；② 位翻转模式下把 `bb_half_delay` 调到 ≥20 nops（<1 MHz）；③ 硬件 SPI 修好后优先用硬件 SPI。真实结论：**任何"读回值可疑"的场合，先用块读交叉验证**。

5. **现象**：复位后 nINT 一直是低，以为芯片没起来。
   **原因**：按 DS §4.1.2（p.21），复位后芯片**故意**拉低 IRQ_N 直到主机清 `RESETC` 并置 `CONFIG0.SYNC`。另外 PHY 侧的中断（link/PLCA 状态变化）在 `INT_MASK0` 未屏蔽前也会让 IRQ_N 保持低。
   **解决**：先完成启动序列（读 STATUS0 → 写 1 清 RESETC → 置 SYNC）；仍有中断就查 MMD31 的 `STS1(0x0018)`（读清）并确认 `IMSK1(0x001C)` 的屏蔽位。

6. **现象**：TC6 数据尾的 `CONFIG_SYNC` 位掉 0、数据收发突然停。
   **原因**：MAC-PHY 内部发生了复位（电磁干扰、供电跌落等），配置全丢。
   **解决**：把 `CONFIG0.SYNC`、`ZARFE`、PHY 参数、MAC 地址、MAC 使能、PLCA 参数做成"可重放"的初始化函数（本仓库 `lan865x_full_init()`），检测到 `cfg_sync_lost` 就整体重放。

7. **现象**：一片 LAN865x 用 AN1699 的参数表也能"跑起来"，但误码/重传偏高。
   **原因**：AN1760 是 **LAN865x Rev.B0/B1** 的配置应用笔记，AN1699 是 **LAN867x** 的；两者参数表不同（本仓库用的是 AN1760 rev F 的 17 条 fixup + SQI 12 条）。
   **解决**：先读 Clause 22 PHY ID 确认型号/版本（LAN865x = `0x0007C1B3`），再选对应参数表。

## 10.10 优劣评价与同类对比

表 10-8 10BASE-T1S 实现方案对比

| 方案 | MCU 侧开销 | 速率 | 多节点 | 生态/资料 | 适用 |
|---|---|---|---|---|---|
| **LAN8651 MAC-PHY（本章）** | 4 线 SPI + 1 中断，需实现 TC6（~900 行） | 10 Mbps | ✅ PLCA 硬件仲裁 | Microchip 资料齐全、Linux 驱动可参考 | 车身域控、传感器环 |
