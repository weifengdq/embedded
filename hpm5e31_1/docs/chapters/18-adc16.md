## 18.3 概述与典型应用

HPM5E00 系列有 **2 个 ADC16**（ADC0/ADC1），16 位分辨率、最高 2 MSPS（16 位）/4 MSPS（12 位），
共 16 路输入，支持差分（DS §1 p.1；RM §40 p.1199）。每路输入可配采样保持周期，
支持 oneshot（单次）、period（周期）、sequence（序列）、preemption（抢占）四种转换模式，
序列/抢占模式可挂 DMA，硬件触发经 **TRGM** 从 PWM/GPTMR 等外设引入。

典型应用：

| 场景 | 推荐模式 | 原因 |
|---|---|---|
| 慢速监控（电池电压、温度） | oneshot + 轮询 | 代码最简单，本仓库例程 |
| 电流环（PWM 中点采样） | sequence/preemption + PWM 触发 + DMA | 与开关噪声对齐，CPU 不参与 |
| 音频/振动（等间隔采样） | period 模式或 GPTMR 触发 | 采样率固定 |
| 多通道扫描 | sequence + DMA | 一次触发扫完整个队列 |

表 18-1 ADC16 关键参数（来源：RM §40 p.1199、SoC 头文件）：

| 参数 | 值 | 出处 |
|---|---|---|
| 分辨率 | 16 bit（8/10/12/16 可选） | `adc16_resolution_t` |
| 转换时钟上限 | 50 MHz | `hpm_soc_feature.h:141` |
| 16 位转换时钟数 | 21 | `adc16_res_16_bits = 21` |
| 最大通道号 | 15 | `ADC16_SOC_MAX_CH_NUM` |
| 满量程码值 | 65535 | `ADC16_SOC_MAX_SAMPLE_VALUE` |
| 内部温度通道 | **无**（`ADC16_SOC_TEMP_CH_EN` 未定义） | SoC 头文件 |
| 硬件过采样 ADC_LOOP | **无**（`HPM_IP_FEATURE_ADC16_HAS_ADC_LOOP` 未定义） | `hpm_soc_ip_feature.h` |
| 差分模式 | 有（`HPM_IP_FEATURE_ADC16_HAS_DIFF_MODE`） | 同上 |

## 18.4 工作原理

### 18.4.1 数据通路

![图 18-1 ADC16 数据通路与触发路径](figures/18/fig-18-1-adc16-datapath.png)

如图 18-1 所示，模拟输入经采样保持进入 16 位 SAR，结果写入 `BUS_RESULT[ch]`（oneshot/period）
或经序列/抢占 FIFO 交给 DMA。转换时钟来自 AHB 总线时钟（本例程用 `board_init_adc_clock(ptr, true)`），
经 `CONV_CFG1.CLOCK_DIVIDER` 分频后必须 ≤50 MHz。

### 18.4.2 采样率公式

- 转换时钟：`conv_clk = adc_input_clk / adc_clk_div`，其中 `adc16_calc_clock_divider()` 会自动选最小合法分频；
- 一次转换占用 `转换时钟数 + 采样保持时钟数` 个 ADC 时钟；
- 16 位模式下 `fs = conv_clk / (21 + sample_cycle)`。

本例程：输入 200 MHz（AHB）→ 分频 4 → 50 MHz；`sample_cycle=20` → fs = 50 MHz / 41 ≈ **1.2195 MSPS**
（日志 `fs(theory): 1219512 Hz`）。

### 18.4.3 两种"读结果"语义

驱动把 oneshot 的结果读取抽象成两种模式（`hpm_adc16_drv.h`）：

| 模式 | 寄存器位 | 行为 | 适用 |
|---|---|---|---|
| 阻塞读 | `BUF_CFG0.WAIT_DIS = 0` | 总线读被挂起直到转换完成，读一次=一次转换 | 轮询采样（本仓库例程） |
| 非阻塞读 | `BUF_CFG0.WAIT_DIS = 1` | 立即返回，靠 `BUS_RESULT.VALID` 判断 | 中断/DMA 前的快速轮询 |

**注意**：`adc16_get_default_config()` 默认给的是 **非阻塞**（`wait_dis = true`，
`hpm_adc16_drv.c:34`），不改成阻塞读就会"时好时坏"（见第 7 节坑 2）。

### 18.4.4 触发链路

序列/抢占模式支持硬件触发，路径为：

```text
PWM0_TRGO / GPTMR 输出 / TRGM0_Pxx  -->  TRGM 输入  -->  TRGM 输出 (ADC0_STRGI / ADCX_PTRGI0A)  -->  ADC16 触发
```

板级宏已备好：`BOARD_APP_ADC16_HW_TRGM_IN = HPM_TRGM0_INPUT_SRC_PWM0_TRGO_0`、
`BOARD_APP_ADC16_HW_TRGM_OUT_SEQ = TRGM_TRGOCFG_ADC0_STRGI`（见 `boards/hpm5e31_1/board.h`）。
本仓库的 PWM 触发 + DMA 例程仍在补充中（见第 11 节待确认项），本章的触发部分依据 RM 与 SDK 参考例程
（`hpm_sdk/samples/drivers/adc/adc16/src/adc16.c`）描述。

## 18.6 例程逐条讲解

### 18.6.1 例程：`samples/adc/adc_basic_poll/`

| 项 | 内容 |
|---|---|
| 路径 | `samples/adc/adc_basic_poll/` |
| 覆盖特性 | oneshot 阻塞轮询、时钟/采样率计算、噪声统计、ENOB 估算、分频×采样周期扫描 |
| 关键配置 | ADC0.IN01(PF26)，16 bit，conv 50 MHz，sample_cycle=20，VREFH 假设 3.3 V |
| 实测现象 | 轮询 605~608 kHz；悬空输入 sd≈49~53 LSB、ENOB≈8.6~8.7 bit |
| 实测日志 | `logs/20261030-110218-adc_basic_poll.log`、`logs/20261030-111916-adc_basic_poll.log` |

关键代码（来自 `samples/adc/adc_basic_poll/src/main.c`）：

```c
/* oneshot 一次读: 阻塞模式下一次读即完成一次转换; 失败最多重试 8 次 */
static bool adc_read_oneshot(uint8_t ch, uint16_t *raw)
{
    for (int i = 0; i < 8; i++) {
        if (adc16_get_oneshot_result(APP_ADC_BASE, ch, raw) == status_success) {
            return true;
        }
    }
    return false;
}

/* main() 里的初始化顺序: 引脚 -> 时钟 -> 公共配置 -> 通道 -> 总线模式 -> 阻塞读 */
board_init_adc16_pins();                                   /* PF26 设为 ANALOG */
s_clk_in_hz = board_init_adc_clock(APP_ADC_BASE, true);    /* AHB 200 MHz */
adc16_calc_clock_divider(s_clk_in_hz, ADC16_SOC_CONV_CLK_FREQ_MAX, &s_clk_div);
cfg.res = adc16_res_16_bits;
cfg.conv_mode = adc16_conv_mode_oneshot;
cfg.adc_clk_div = s_clk_div;
adc16_init(APP_ADC_BASE, &cfg);
ch_cfg.ch = APP_ADC_CH;                                    /* 1 */
ch_cfg.sample_cycle = APP_ADC_SAMPLE_CYCLE;                /* 20 */
adc16_init_channel(APP_ADC_BASE, &ch_cfg);
adc16_enable_oneshot_mode(APP_ADC_BASE);                   /* HPM5E31 必须 */
adc16_set_blocking_read(APP_ADC_BASE);                     /* 默认是非阻塞的! */
```

这段代码解决三个"第一次用 ADC16 必踩"的问题：通道引脚要先配 ANALOG、HPM5E31 要开 bus mode、
默认是非阻塞读。

如图 18-2 所示，**采样保持时间越长，噪声越小、ENOB 越高**（33~105 LSB → 7.6~9.5 bit），

### 18.7.3 PWM 触发 + DMA 连续采样实测

例程 `samples/adc/adc_pwm_trigger_dma/` 用 PWM0 TRGO（内部触发，不占引脚）经 TRGM 触发 ADC0
序列转换，结果由序列 DMA 连续写入 non-cacheable 缓冲（日志 `logs/20261030-120354-adc_pwm_trigger_dma.log`）：

表 18-6 PWM 触发 + DMA 实测：

| 指标 | 1 s 测试 | 2 s 测试 |
|---|---|---|
| 触发频率 | 20 kHz | 20 kHz |
| 实际转换数 | 20000 | 40001 |
| 实际采样率 | **20000.0 SPS**（0% 误差） | 20000.5 SPS（+0.0025%） |
| 触发间隔抖动 pp | **1.00 µs** | 4.46 µs（一次异常） |
| 缓冲采样值 sd | 34.1 LSB | 35.5 LSB |

对比第 5.1 节的轮询（607 kHz、抖动大）：**PWM 触发 + DMA 把采样时刻交给硬件**，
采样率精确、抖动只有 1 µs 量级，CPU 只在中途读一次结果；这是电流环/音频等场景的标准做法。
本测试只覆盖 1~2 s，长期抖动与 shell 串口是否干扰仍需专项验证（见第 11 节）。

### 18.7.4 软件过采样对 ENOB 的改善（实测）

HPM5E31 没有硬件 ADC_LOOP（见 2.1 节表 18-1），只能用软件累加平均。例程命令
`adcavg [groups]` 实测"m 次采样平均"对噪声的影响（PF26 悬空，每组 256 个平均结果）：

表 18-7 软件过采样实测（logs/20261030-115554-adc_basic_poll.log）：

| 平均次数 m | 组数 | 均值 (LSB) | sd (LSB) | pp (LSB) | ENOB | 折算轮询 (kHz) |
|---|---|---|---|---|---|---|
| 1 | 256 | 35537.59 | 80.33 | 1482 | 7.92 | 476.5 |
| 2 | 256 | 35501.70 | 84.57 | 1275 | 7.87 | 657.5 |
| 4 | 256 | 35479.89 | 44.78 | 597 | 8.81 | 746.2 |
| 16 | 256 | 35465.09 | 13.88 | 160 | 10.58 | 832.7 |
| 64 | 256 | 35461.10 | 5.88 | 49 | 11.76 | 857.3 |

结论：

- m≥4 后 sd 近似按 1/√m 下降（44.78 → 13.88 → 5.88），ENOB 随之上升 7.9 → 11.8 bit；
- m=1 与 m=2 的 sd 反而更大（80.33 / 84.57），说明**悬空输入的基线噪声本身在漂**，
  单次测量不足以代表"一次采样"的真实噪声；
- 代价：m 次平均后有效采样率降为 1/m（表中"折算轮询"是吞吐而非 fs）；
  要 10 kHz 有效输出且 m=16，ADC 至少要 160 kHz 的转换能力，本板轮询达不到，必须上 DMA。

### 18.7.5 精度结论的适用边界

- 以上 ENOB 是 **悬空输入 + 3.3 V 假设参考** 下的噪声指标，**不能当作 ADC 的绝对精度**；
- 若按 3.3 V VREFH 换算，1 LSB ≈ 50.35 µV，sd≈50 LSB ≈ 2.5 mV；
- 要评估真实精度必须外接低噪声基准源（方法见第 11 节）。

## 18.8 性能与调优

1. **要高速就上 DMA**：轮询 607 kHz 已是 CPU 上限；序列 + DMA 才能接近 1.2 MSPS。
2. **采样保持时间按源阻抗选**：高阻源（>10 kΩ）用 100~511 周期；低阻运放缓冲可降到 10~20。
3. **转换时钟别贪高**：50 MHz 是 IP 上限，但 fs 还要除以 (21+sample_cycle)；
   降低 conv clk 并保持相同 fs 可减少功耗/噪声。
4. **触发对齐**：电流采样要把触发点放在 PWM 中点（远离开关沿），见第 14/17 章。
5. **参考电压**：VREFH 的纹波直接进结果，PCB 上要给 VREFH 加 1 µF+100 nF 并联去耦。

## 18.9 坑与注意事项

1. **现象**：`adc16_get_oneshot_result()` 一直返回失败、读到 0。
   **原因**：HPM5E31 的 `ADC_SOC_BUSMODE_ENABLE_CTRL_SUPPORT = 1`，oneshot 必须先
   `adc16_enable_oneshot_mode()` 打开 bus mode，否则 `BUS_RESULT.VALID` 不置位。
   **解决**：初始化后调用一次（本仓库例程已在 `main.c` 中处理）。
2. **现象**：连续读时好时坏（第 1 次成功、第 2 次失败）。
   **原因**：默认 `wait_dis = true`（非阻塞），两次读之间转换还没完成。
   **解决**：`adc16_set_blocking_read()`，或按 SDK 的"非阻塞两次读"模式。
3. **现象**：移植 SDK 的 `adc16_temperature` 例程编译不过。
   **原因**：HPM5E31 **没有** `ADC16_SOC_TEMP_CH_EN` 和 `ADC16_SOC_TEMP_CH_NUM`，
   SDK 该例程只适用于 HPM6750 等带内部温度通道的型号。
   **解决**：温度用独立 TSNS 外设（`samples/power/tsns_temp/`）。
4. **现象**：配置 `adc_loop_exp` 无效。
   **原因**：HPM5E31 没有 `HPM_IP_FEATURE_ADC16_HAS_ADC_LOOP`（硬件过采样），
   结构体字段根本不存在。
   **解决**：软件多次采样后平均（见第 11 节待确认项）。
5. **现象**：读数随采样时间变长而系统性偏移。
   **原因**：悬空输入的漏电流/寄生电容在采样保持阶段充放电；有源输入时不会这么明显。
   **解决**：接低阻源，或加长采样时间后做两点校准。

## 18.10 优劣评价与同类对比

表 18-5 ADC 能力对比（HPM 数据来自本板实测/RM，其余为厂商公开参数）：

| 项 | HPM5E31 ADC16（实测） | STM32H7 ADC | TC397 ADC |
|---|---|---|---|
| 分辨率 | 16 bit | 16 bit | 12 bit |
| 最高速率 | 2 MSPS（16 位，DS） | 3.6 MSPS | ~5 MSPS |
| 通道数 | 2×16 路（含差分） | 3×16 路 | 多组 |
