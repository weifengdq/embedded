## 3. 三种标准测试台（bench）

**Bench A：MCU 双节点自测（无上位机，最快）**
DUT 跑 CAN0，测试节点跑 CAN1，二者物理同总线。用于协议栈早期调试。

**Bench B：上位机 + CAN 网关（CAN 类协议的标准做法）**
```
主机 vcan0  <--UDP(cannelloni)-->  ENET  <--->  MCU CAN1(网关)  <-->  总线  <-->  MCU CAN0(DUT)
```
- 板端固件 = DUT + `app_can_gw` 组件（CAN1 当网关）；上位机 `host/can_bridge/` 起 cannelloni + vcan0。
- 上位机工具（python-can / udsoncan / canopen / pyxcp / candump …）直接操作 `vcan0`，看到的就是真实 CAN 总线。
- 上位机 CAN ID 与 DUT 的 ID 约定见 §5。
- vcan 必须限速：`sudo tc qdisc add dev vcan0 root tbf rate 500kbit latency 100ms burst 4000`（默认 vcan 无速率限制，会淹没 MCU）。

**Bench C：以太网应用直连（SOME/IP、XRCE-DDS、PTP、DLT 等）**
主机 `enp6s0`(192.168.2.1) ↔ 板 `192.168.2.100`，UDP/TCP 端口分配见 §6。

> 板卡只有一块：**任何烧写/串口操作必须走 `scripts/hwrun.sh`（内部 board lock 串行，PID 自愈锁 `scripts/hwlock.sh`）**，
> 禁止直连 J-Link / 串口，否则会打断别人的测试。锁等待用 `--lock-wait 1800`。

## 4. 共享组件 API 契约（tp-infra 提供，其他成员只调用）

### 4.1 `components/app_can` —— CAN FD 节点
```c
#include "app_can.h"
/* 经典 500k 或 FD 1M/2M，返回 0 成功 */
int  app_can_init(app_can_t *c, MCAN_Type *base, const app_can_cfg_t *cfg);
int  app_can_send(app_can_t *c, const app_can_frame_t *f, uint32_t timeout_us);   /* 0 成功 */
int  app_can_recv(app_can_t *c, app_can_frame_t *f, uint32_t timeout_us);         /* 0=收到，1=超时 */
void app_can_set_filter(app_can_t *c, const app_can_filter_t *flt, int n);
uint64_t app_can_now_us(void);          /* 单调时基，用于时延统计 */
void app_can_get_stats(app_can_t *c, app_can_stats_t *st); /* 收发计数/错误/总线关闭 */
```
- `app_can_frame_t`：`id/ext/rtr/fd/brs/len/data[64]/ts_us`。
- 初始化内部完成 `board_init_can()/board_init_can_clock()/board_can_transceivers_enable()`，不要重复调用。
- CAN FD 默认：仲裁 1 Mbit/s、数据 2 Mbit/s、TDC 开、DLC≤64。

### 4.2 `components/app_lwip` —— 应用层 lwIP
```c
#include "app_lwip.h"
int  app_lwip_init(const app_lwip_cfg_t *cfg); /* RGMII+YT8011，静态 IP，等 link up */
struct netif *app_lwip_netif(void);
uint32_t app_lwip_now_ms(void);
void app_lwip_poll(void);        /* 主循环调用：sys_check_timeouts + 收发驱动 */
int  app_udp_socket(const ip_addr_t *local, uint16_t port); /* 建好并 bind 的 socket */
```
- 默认 `IP=192.168.2.100/24 GW=192.168.2.1`，MAC 可用 board 默认。
- 单线程裸机：UDP 收发在 `app_lwip_poll()` 驱动的回调里做，回调要短（<100µs）。
- lwIP 配置沿用 `samples/enet/enet_lwip_iperf/inc/lwipopts_app.h` 的内存预算；新增缓冲要核算。

### 4.3 `components/app_can_gw` —— cannelloni 兼容网关
```c
#include "app_can_gw.h"
int app_can_gw_init(const app_can_gw_cfg_t *cfg); /* 本端 UDP 端口 + 对端 IP/端口 + CAN 通道映射 */
void app_can_gw_poll(void);   /* 主循环调用：UDP<->CAN 双向搬运 */
```
- 线上格式 = cannelloni v2：UDP 载荷 = 5B 头（version=2, op, seq, count u16 LE）+ count × Linux `struct canfd_frame`（can_id u32、len u8、flags u8、__res0、__res1、data[64]）。
- 目的：主机 stock `cannelloni` 工具直接对接 → `vcan0`。
- CAN1 = vcan0（默认通道），CAN2/CAN3 可选映射到 vcan2/vcan3，端口 4000+ch。
- 统计 `cfg` 里可查：rx_udp/tx_udp/rx_can/tx_can/drop。

### 4.4 例程统一外壳
每个 `samples/app/<name>/src/main.c`：
```c
#include "bsp.h"
int main(void)
{
    board_init();                 /* 板级：时钟/引脚/串口 */
    bsp_init();                   /* letter-shell 控制台 */
    /* ... 你的初始化 ... */
    printf("[app] <name> ready\r\n");
    while (1) {
        bsp_shell_poll();
        /* app_lwip_poll(); app_can_gw_poll(); ... */
    }
}
```
- 每个例程必须在串口打印**一行 PASS/FAIL 结论**和关键数字（hwrun 日志抓取用）；shell 里再提供可重跑命令（如 `run`、`bench`、`stat`）。
- README.md 写：硬件连接、命令、实测现象/数字、日志路径、易错点。

## 5. CAN ID 分配（防止各例程撞车；上位机侧同表）

| 用途 | CAN ID（11 位） | 说明 |
|---|---|---|
| UDS 物理请求 / 响应 | 0x7E0 / 0x7E8 | ISO-TP，经典帧，DLC=8 |
| UDS 功能请求 | 0x7DF | 广播 |
| ISO-TP 裸测试 | 0x700 / 0x708 | 回显节点 |
| J1939 | 29 位，按 PGN/SA 编码 | 引擎 ECU 源地址 0x00，测试仪 0xF9 |
| CANopen | NMT 0x000 / SYNC 0x080 / EMCY 0x081 / TPDO1 0x181 / RPDO1 0x201 / SDO 0x601-0x602 / SDO 响应 0x581-0x582 / 心跳 0x701-0x702 | 节点 1、2 |
| XCP | 0x555（CMD）/ 0x556（RES） | 或按 A2L 配置 |
| 裸 CAN 网关自测 | 0x123 / 0x321 | 与既有 mcan_two_node 一致 |

- 一条总线上的例程要能**共存**（DUT 与网关是同一固件，不冲突）；不要用 0x000/0x7FF 之类特殊 ID。
- 扩展帧用于 J1939 必须 29 位；过滤器掩码要正确（J1939 常按 PF/PS 过滤）。

## 7. 上板测试规范

```bash
cd hpm5e31_1
# 编译 + 烧写 + 抓 15s 串口 + 自动存档 logs/<时间戳>-<例程>.log
bash scripts/hwrun.sh app/<name> --secs 15 --send "run;bench" --lock-wait 1800
# 重跑不重编译
bash scripts/hwrun.sh app/<name> --secs 10 --send "stat" --no-build
```
- `--send` 串内用 `;` 分隔（serial_cap.py 拆分后逐条发送，必须给 --send 加引号，否则外层 shell 会解释分号）；letter-shell 没有 sleep 命令：需要延时就拆成两次 hwrun（第二次加 --no-build），或在固件里注册自己的 shell 命令。
- 日志是**书稿证据**：路径写进章节"实测日志"列，不要删除。
- 编译失败先读 `/tmp/build_*.log`；板锁超时说明有人在长测，稍等重试。
- 长时间测试用 `--secs 60` 级别，一次跑完多组参数，避免占锁过久。
- 需要「烧写后立刻在主机侧联调」（如 SOME/IP）时，用 `--post "host 命令"` 仍持同一把锁执行：
  `bash scripts/hwrun.sh app/someip_rpc --secs 20 --send "run" --post "timeout 80 bash host/someip/run_client.sh" --lock-wait 1800`
  单次持锁 ≤90s；--post 内命令必须带 timeout。
- **禁止自己 flock/加锁**；只用 hwrun.sh（或 --post）。板锁为 PID 目录自愈锁，被 kill -9 后下一个等待者自动清理；异常时看 `/tmp/hpm5e31_hw.lock.d/{pid,since,what}`。
- 每次上板前**先确认别人的测试没在跑**（lock 会等，但不要故意长时间占用）。
- 不得修改 `scripts/flash.sh`、`scripts/serial_cap.py` 的端口/波特率默认值。

## 9. 上位机工具规范

- 目录 `host/<方向>/`：源码 + `README.md`（依赖、构建、运行、预期输出）+ 一键脚本（`run_*.sh`）。

- C++：CMake，产物进 `host/<方向>/build/`（.gitignore 里排除 build），依赖在 README 写清（apt 包名）。
- Rust：cargo，`Cargo.toml` + `src/main.rs`；需要联网时用代理 `export https_proxy=http://<proxy>:7890`。
- 每个方向**至少 1 个 Python**，鼓励再给 1 个 C++ 或 Rust 版本（用户要求 C++/Python/Rust 中 1~3 种）。

## 10. 资源与实时性约束

- CPU 480 MHz，XIP Flash 执行（关键热路径可放 ILM/AHB SRAM）；lwIP 应用注意 `printf` 不要进回调。
- 中断里只做搬运/置标志；协议解析放主循环。
- 单个例程镜像尽量 < 200 KB（Flash 1 MB 合封）。
- 周期性任务用 GPTMR 或 `app_can_now_us()` 轮询；不要依赖 `board_delay_ms` 做精确节拍。
- 有 DMA 可用（XDMA/HDMA），但先保证正确性；吞吐再优化。
