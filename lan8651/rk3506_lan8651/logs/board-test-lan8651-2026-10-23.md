# LAN8651 (10BASE-T1S) 板端测试记录 — 2026-10-23

> 板卡：HZ-RK3506G2_MiniEVM (TF)，内核 6.1.118（本次回移 LAN865x/PLCA）
> 串口：`/dev/ttyACM0` 1500000
> 对端：USB-10BASE-T1S `184f:0051`，主机网卡 `enx001ec0d1c337`

## 1. 结论

✅ **LAN8651 已跑通**：
- `t1s0` 出现，`10baseT1S_P2MP/Half`，10 Mbps，MAC `02:00:00:10:86:51`；
- PLCA **Slave（板 Node1 / 主机 Node0）**：`Status: on`，ping 3/3，TCP **8.86 Mbps**；
- PLCA **Master（板 Node0 / 主机 Node1）**：`Status: on`，主机 `Status: on`，TCP **8.93 Mbps**；
- UDP 9 Mbps：丢包 **0.13%**，jitter 0.093 ms；
- PLCA 关闭（CSMA）对比：TCP **6.72 Mbps**（PLCA 提升约 32%）。

## 2. 根因与修复（最重要）

### 2.1 错误引脚映射（前半程一直读 0）

J7 的 SPI0 信号**不是** RK3506 专用 SPI0 引脚（GPIO0_C0-C3），而是经 **RM_IO 矩阵**：

| J7 | 网络 | 实际 SoC 引脚 |
| --- | --- | --- |
| 19 | SPI0_MOSI | GPIO0_B1 / RM_IO9 |
| 21 | SPI0_MISO | GPIO0_B2 / RM_IO10 |
| 23 | SPI0_CLK | GPIO0_B0 / RM_IO8 |
| 24 | SPI0_CSN0 | GPIO0_B3 / RM_IO11 |

用 `spi0_clk_pins`/`spi0_csn0_pins`（C0-C3）时：
- 驱动报 `RESETC timeout, STATUS0=0x00000000`；
- `ctrl read reply mismatch ... rx=00000000`；
- GPIO 位翻转（16-19）四种模式全 0；
- 短接 J7-19/21 回环也全 0。

### 2.2 正确 pinctrl 后回环通过

改成 RM_IO8-11 后，用 GPIO 位翻转 + 短接 J7-19/21：
```
GPIO sck=8 mosi=9 miso=10 cs=11 mode=0 RX: 00 00 08 00 00 00 00 00
mode 1/2/3 同样通过
```
→ 证明 B0-B3 / J7 / GPIO 路径正常。

### 2.3 UART2/UART3 复用冲突

J7 的 SPI0 引脚与板载扩展接口复用：
- RM_IO8 (B0) = UART3_TX（北斗/GPS）
- RM_IO9 (B1) = UART2_TX（RS485_1）
- RM_IO10 (B2) = UART2_RX（RS485_1）

不禁用时 pinctrl 报：
```
rockchip-pinctrl pinctrl: could not request pin 8 (gpio0-8)
    from group rm-io8-spi0-clk on device rockchip-pinctrl
```
在 DTS 中加：
```dts
&uart2 { status = "disabled"; };
&uart3 { status = "disabled"; };
```
后 pinctrl 显示：
```
pin 8  (gpio0-8):  ff120000.spi  function rm_io8  group rm-io8-spi0-clk
pin 9  (gpio0-9):  ff120000.spi  function rm_io9  group rm-io9-spi0-mosi
pin 10 (gpio0-10): ff120000.spi  function rm_io10 group rm-io10-spi0-miso
pin 11 (gpio0-11): ff120000.spi  function rm_io11 group rm-io11-spi0-csn0
```

## 4. 接口命名问题

LAN865x 是 built-in，probe 早于 RK GMAC，会抢 `eth0`。已用 `/etc/init.d/S39rename-t1s`：
- `spi0.0` → `t1s0`
- `ff4c8000.ethernet` → `eth0`

`/etc/network/interfaces`：
```
auto eth0
iface eth0 inet dhcp

auto t1s0
iface t1s0 inet static
    address 192.168.1.100
    netmask 255.255.255.0
```

板端：

PLCA settings for t1s0:

iperf3 TCP 15 s（-O 3）：**8.86 Mbps**（receiver），180 retr。

### 5.2 Master（板 Node0 / 主机 Node1）

板端：
```
PLCA settings for t1s0:
    Enabled: Yes
    local node ID: 0 (coordinator)
    Node count: 8
    TO timer: 32 BT
    Burst count: 0 (disabled)
    Burst timer: 128 BT
PLCA status of t1s0:
    Status: on
```
主机 `ethtool --get-plca-status enx001ec0d1c337` → `Status: on`。
ping 5/5，RTT 1.00–1.20 ms。
iperf3 TCP 15 s：**8.93 Mbps**（receiver），176 retr。

### 5.3 调优对比

| 场景 | 速率 | Retr |
| --- | --- | --- |
| PLCA Master, TO=32, Burst=0 | 8.87 Mbps (20 s) | 198 |
| PLCA Master, TO=32, Burst=2 | **8.94 Mbps** (15 s) | 101 |
| PLCA Master, TO=64, Burst=0 | 8.76 Mbps (15 s) | 115 |
| PLCA Master, TO=16, Burst=0 | **5.74 Mbps** (15 s) | 477 |
| PLCA Slave, TO=32 | 8.86 Mbps (15 s) | 180 |
| PLCA Master, TO=32, **60 s soak** | **8.86 Mbps** (60 s) | 649 |
| PLCA 关闭（CSMA） | 6.72 Mbps (20 s) | 69 |
| 反向（板→主机, Master） | 8.44 Mbps (20 s) | 6 |
| UDP 9 Mbps | 8.99 Mbps | 0.13% loss |

结论：
- PLCA 比 CSMA 提升约 **32%**；
- `to-tmr=32/64` 都好，**16 明显变差**；
- `burst-cnt=2` 略优、重传更少；
- 15 MHz SPI 足够。

## 6. 风险/待办

1. 最终镜像需把 `S39rename-t1s` + `interfaces` 写进 buildroot overlay（`scripts/17`）。
2. 25 MHz SPI 压测（可选）。
3. 多节点（>2）PLCA、长稳 soak。
4. RS485_1/北斗与 LAN8651 硬件复用，不能同时使用。
5. USB 适配器偶发 wedge，先复位再测。
